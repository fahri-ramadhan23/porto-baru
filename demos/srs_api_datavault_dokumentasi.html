1. Spesifikasi Kebutuhan Perangkat Lunak (SRS) & Arsitektur Sistem

Dokumen ini mendefinisikan spesifikasi fungsional, non-fungsional, kontrak antarmuka REST API, pemodelan gudang data Data Vault 2.0, prosedur deployment, serta ringkasan evaluasi uji keamanan sebelum serah terima source code.

1. Lapisan Aplikasi & API

Layanan backend FastAPI/REST dengan autentikasi Bearer JWT (RS256), pembatasan laju (Rate Limiting), dan penjaminan idempotensi transaksi.

2. Basis Data Operasional (OLTP)

PostgreSQL 16 dengan skema ternormalisasi (3NF), indeks komposit pada kolom kunci pencocokan, serta pencatatan audit trail perubahan status.

3. Pipeline ETL & Staging

Ekstraksi inkremental terjadwal menggunakan CDC/timestamp, perhitungan SHA-256 Hash Key deterministik, dan validasi skema sebelum pemuatan.

4. Enterprise Data Vault 2.0

Pemisahan entitas bisnis murni (Hub), relasi transaksi (Link), dan atribut deskriptif historis (Satellite) untuk auditabilitas penuh.

Tabel Kebutuhan Fungsional Utama (Kutipan SRS)

ID Kebutuhan Modul Deskripsi Spesifikasi Kriteria Penerimaan (Acceptance Criteria)
FR-ING-01 Ingesti Transaksi Sistem menerima payload transaksi harian melalui endpoint REST API terautentikasi dan memvalidasi keunikan idempotency_key. Request duplikat dalam jendela 24 jam mengembalikan HTTP 200 beserta payload respons awal tanpa menduplikasi baris di tabel trx_orders.
FR-DV-02 Pemodelan Data Vault Setiap perubahan atribut profil mitra disimpan sebagai baris baru (append-only) pada tabel Satellite dengan penanda load_dts dan hash_diff. Baris baru hanya disisipkan apabila nilai hash_diff berbeda dari rekaman aktif terakhir; riwayat lama tetap utuh 100%.
NFR-SEC-03 Keamanan API Seluruh parameter kueri wajib melalui prepared statement / ORM parameterization dan token kedaluwarsa dalam 15 menit. Pengujian injeksi SQL dan manipulasi payload JWT menghasilkan HTTP 401/422 tanpa kebocoran jejak stack internal.

2. Dokumentasi Kontrak REST API (Standar OpenAPI 3.0 / Swagger)

POST /api/v2/reconciliation/submit — Mengirimkan batch transaksi untuk rekonsiliasi dan sinkronisasi ke staging gudang data.

openapi: 3.0.3
paths:
  /api/v2/reconciliation/submit:
    post:
      summary: Mengirimkan data transaksi tervalidasi ke layanan rekonsiliasi
      security:
        - BearerAuth: []
      parameters:
        - in: header
          name: X-Idempotency-Key
          required: true
          schema:
            type: string
            format: uuid
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [kode_mitra, nomor_referensi, nominal_idr, waktu_transaksi]
              properties:
                kode_mitra: { type: string, example: "MTR-JKT-0042" }
                nomor_referensi: { type: string, example: "INV-20261126-8891" }
                nominal_idr: { type: integer, minimum: 1000, example: 2750000 }
                waktu_transaksi: { type: string, format: date-time, example: "2026-11-26T08:15:00+07:00" }
      responses:
        '201':
          description: Transaksi berhasil divalidasi dan masuk antrean sinkronisasi
        '409':
          description: Konflik nomor referensi dengan payload berbeda
        '422':
          description: Kegagalan validasi tipe data atau batas nominal
