How to Eliminate Cursor Jitter in Real-Time Python Computer Vision Apps Using an Exponential Low-Pass Filter

Written by Moh Fahri Ramadhan • Portfolio • GitHub

When I built a hands-free accessibility mouse controller in Python using OpenCV and MediaPipe Face Mesh, getting the raw facial landmarks running at 30 FPS was the easy part. Tracking iris landmarks 468 through 477 gave me the user's gaze coordinates in a few lines of code.

The real problem showed up the moment I wired those coordinates directly into pyautogui.moveTo(x, y). Even when a user held their head completely still in front of a 1080p webcam, CMOS sensor noise and sub-pixel lighting shifts caused the cursor to vibrate constantly across a 15-pixel radius. Trying to click a small button felt like threading a needle on a moving train.

In this tutorial, we'll look at why raw landmark streams jitter, why a naive moving-average buffer feels sluggish, and how an Exponential Low-Pass Filter (EMA) paired with a micro-deadzone solves cursor tremor in under 30 lines of Python.

1. Why Sub-Pixel Camera Noise Turns Into 15-Pixel Screen Jumps

MediaPipe Face Mesh estimates 468 3D landmarks independently on every incoming frame. Because each frame is inferred separately from a compressed webcam stream, tiny fluctuations in pixel brightness shift the normalized output coordinates (x, y) ∈ [0.0, 1.0] by roughly ±0.004 from frame to frame.

When you crop an active head-movement bounding box (say, [0.25, 0.75]) and map it onto a 1920x1080 display using numpy.interp, that tiny 0.004 sensor wobble gets amplified by a factor of nearly 4,000—resulting in a 15-pixel jump on screen thirty times per second.

2. Implementing the First-Order Exponential Low-Pass Filter

Unlike a simple rolling window that weights old frames equally and adds noticeable lag during fast head movements, a first-order exponential low-pass filter blends the new measurement with the previous filtered state using a smoothing factor alpha ∈ (0, 1]:

import numpy as np

class GazeCursorFilter:
    def __init__(self, alpha: float = 0.25, deadzone_px: float = 2.5):
        if not (0.0 < alpha <= 1.0):
            raise ValueError("alpha must be between 0.0 (exclusive) and 1.0 (inclusive)")
        self.alpha = alpha
        self.deadzone_px = deadzone_px
        self.prev_x: float | None = None
        self.prev_y: float | None = None

    def update(self, norm_x: float, norm_y: float, screen_w: int, screen_h: int) -> tuple[int, int]:
        # Map active normalized camera region to screen resolution
        target_x = float(np.interp(norm_x, [0.20, 0.80], [0, screen_w]))
        target_y = float(np.interp(norm_y, [0.25, 0.75], [0, screen_h]))

        if self.prev_x is None or self.prev_y is None:
            self.prev_x, self.prev_y = target_x, target_y
            return int(target_x), int(target_y)

        # First-order low-pass filter: y[n] = alpha * x[n] + (1 - alpha) * y[n-1]
        smooth_x = self.alpha * target_x + (1.0 - self.alpha) * self.prev_x
        smooth_y = self.alpha * target_y + (1.0 - self.alpha) * self.prev_y

        # Suppress sub-deadzone micro-tremors when the user is focusing on a button
        delta = np.hypot(smooth_x - self.prev_x, smooth_y - self.prev_y)
        if delta < self.deadzone_px:
            return int(self.prev_x), int(self.prev_y)

        self.prev_x, self.prev_y = smooth_x, smooth_y
        return int(smooth_x), int(smooth_y)

3. Tuning Alpha and Gesture Debouncing in Practice

After logging frame telemetry to CSV across multiple webcam setups, three practical lessons stood out:

  • alpha = 0.25 is the sweet spot at 30 FPS: Values above 0.50 let high-frequency sensor noise bleed through, while values below 0.15 introduce a "swimming through honey" delay that causes users to overshoot buttons.
  • Pair movement filtering with frame-count gesture debouncing: If you trigger a left-click from a smile ratio (Euclidean mouth width-to-height ratio > 0.65), require the threshold to hold across 8 consecutive frames with a 0.5s cooldown so talking or blinking doesn't fire accidental clicks.
  • Disable PyAutoGUI's default 100ms pause: Always set pyautogui.PAUSE = 0 and pyautogui.MINIMUM_DURATION = 0; otherwise PyAutoGUI sleeps for 100ms on every moveTo call and caps your entire OpenCV loop at 10 FPS.
